recording → transcript

How a recording
becomes text you can use

In one line: The agent cannot hear. The audio goes to a separate program that genuinely listens, and only then does the agent get a turn.
The three diagrams below are the whole mechanism.

圖一 · 從一個檔案到兩個檔

閘門卡在合併之後。這條線上的錯全都是安靜的。

為什麼要這樣設計

切段是它聽得完的原因，也是它會壞的原因：整段消失、尾巴被吃掉、接縫處標籤對調。四道閘存在，是因為這些都不報錯——合併後的檔一樣讀得順。

Diagram 1 · From one file to two files

The gate sits in the middle, after the merge. Every failure on this line is silent.

Why it works this way

Cutting the audio up is what makes it listenable at all, and also what breaks it: segments come back empty, tails go missing, labels flip at the seams. The gates exist because none of that reports an error — the merged file reads continuous either way.

圖二 · 三個要先問、不要猜的決定

「幾個人在講」不改變怎麼轉錄，只決定要不要分離講者。

為什麼要這樣設計

指紋——只有他會講的那兩三句話——是你有、模型沒有的唯一東西，所以名單要在開跑前補齊。同一個檔跑兩次是兩份文件，重跑證明不了名字，只有本人可以。

Diagram 2 · Three things to ask, not guess

"How many people" does not change how the audio is transcribed. It decides whether speaker separation is worth doing.

Why it works this way

The fingerprints — the two or three things only that person would say — are the one thing you have that the model does not, which is why an incomplete roster gets fixed before the run. And because two runs of one file are two different documents, a re-run can never settle a name; only the person can.

圖三 · 拿到之後

逐字稿不是任何人要的東西，它是原料。

為什麼要這樣設計

音檔留在旁邊，是因為轉錄不可重現——錄音是唯一還能回頭對的東西。而那是 30 天的暫存區：做完、正確、沒人接的逐字稿，一樣是弄丟了。

Diagram 3 · Once you have it

Nobody wants a transcript. It is raw material.

Why it works this way

The audio is kept beside the transcript because transcription is not reproducible — the recording is the only thing anyone can go back to. And that folder is a 30-day staging area: a transcript that is finished, correct and unfiled is still a transcript that was lost.

整台機器的兩條原則

錯了不會報錯
  • 掉一段、標籤對調、名字聽錯，出來的檔都很正常
  • 四道閘各擋一種，少跑一道等於沒驗
兩個檔才算做完
  • 逐字稿與音檔同名同層，缺一個就還沒完
  • 正文永遠不改，更正只放在上方那張表

Two rules for the whole machine

Nothing errors out
  • A dropped segment, swapped labels, an invented name — the file looks normal in all three cases
  • Each gate catches one silent failure; skipping one is not verifying
Done means two files
  • The transcript and the audio it came from, same name, same folder — one without the other is not done
  • The body is never edited: corrections live in a table above it
