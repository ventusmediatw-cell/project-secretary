audio → text

How a recording
becomes text you can use

In one line: AI cannot hear. A recording has to be turned into text by another program first, before AI gets a turn.
The three diagrams below are the whole mechanism.

圖一 · 從檔案到那一條命令

兩個判斷點都在動手之前。跳過它們，失敗是安靜的。

為什麼要這樣設計

走英文／中文那條時，白名單外的檔案，錯誤是服務端丟回來的 HTTP 碼，不會寫「格式不對」——而 Mac 預設錄音是 .aiff、手機錄影是 .mov，正好兩個都不在（高棉語那條會先自己重新編碼，不受這個限制）。多人對話則是另一種安靜：這條管線不做講者分離，誰講了什麼重要的話，就得換能「聽」的多模態模型。

Diagram 1 · From a file to the one command

Both decision points come before you start. Skip them and the failure is silent.

Why it works this way

On the English and Chinese route, a file outside the allowlist comes back as an HTTP code from the server, never as "wrong format" — and a Mac records to .aiff by default while a phone films to .mov, so both miss the list (the Khmer route re-encodes on its own and is not bound by this). A multi-person conversation is silent in a different way: this pipeline does not separate speakers. If it matters who said the important line, you need a multimodal model that can actually listen.

圖二 · 語言要你自己講

進去什麼語言，出來就是什麼語言。

為什麼要這樣設計

這不是翻譯器。要換一種語言，是拿到逐字稿之後的另一步——這樣「他到底說了什麼」和「誰把它翻成什麼」才不會混成同一份檔案。高棉語那條也因此要小心：兩次跑出來的字不同，不代表誰記錯了。

Diagram 2 · You name the language yourself

Whatever language goes in is the language that comes out.

Why it works this way

This is not a translator. Changing language is a separate step after the transcript exists — that way "what he actually said" and "how someone translated it" never end up in the same file. The Khmer route needs the same care: two runs that come out differently are not a sign that anyone misremembered.

圖三 · 拿到字之後

逐字稿不是任何人要的東西，它是原料。

為什麼要這樣設計

改正文會毀掉唯一的紀錄：模型到底聽成什麼。留著它，日後才有辦法用更好的模型重新對一次。高棉語沒有固定原稿可以重對，能回頭對的只有錄音檔本身。

Diagram 3 · After you have the text

Nobody wants a transcript. It is raw material.

Why it works this way

Editing the text destroys the only record there is of what the model actually heard. Keep it, and a better model can be run against it later. Khmer has no fixed reference version to check against — the only thing to go back to is the recording itself.

整台機器的兩條原則

判斷點都在前面
  • 格式、人數、語言，三件事在動手前就要決定
  • 它們出錯時都不會報錯，只會給你一份看起來很正常的東西
沒做的事就說沒做
  • 不做講者分離、不做翻譯
  • 名字與數字的正確性，由你在交出去之前確認

Two rules for the whole machine

The decisions all come first
  • Format, number of speakers, language: all three are settled before you start
  • When they go wrong nothing errors out — you just get something that looks perfectly normal
Say plainly what it does not do
  • No speaker separation, no translation
  • Names and numbers are yours to check before you hand the file over
